# Pull Request Standards

## Required information

Every pull request should include:

- a clear summary of the change
- the reason for the change
- testing or verification notes
- any known follow-up work

## Scope

Pull requests should stay focused on the requested change. Avoid bundling unrelated work into a single request.

## Review readiness

A pull request is ready for review when:

- the change is complete
- the summary is accurate
- tests and linting have been attempted locally
- related documentation is updated where needed
