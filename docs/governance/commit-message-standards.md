# Commit Message Standards

## Format

Use concise, descriptive commit messages that explain the change.

### Recommended structure

- feat: add support for ...
- fix: resolve issue with ...
- docs: update governance guidance
- chore: maintain repository tooling
- refactor: simplify ...
- test: add or update tests

## Guidance

- Use the imperative mood.
- Keep the subject line short and specific.
- Include a body when the change needs context.
- Reference related issues when helpful.
